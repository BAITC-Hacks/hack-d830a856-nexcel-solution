# NEXCEL Wind AI

Детерминированный контур проекта строит почасовой прогноз нормализованной
мощности для двух турбин ВЭС. Агентный слой не вычисляет прогноз сам: он
получает погодные данные через tool, передаёт их локальной LightGBM-модели и
формирует понятный ответ.

## Поток данных

1. src.train.build_train_set читает фактические SCADA XLSX/CSV, очищает
   значения, приводит временную ось к UTC и выполняет почасовой ресемплинг.
2. src.tools.weather_tool загружает исторический прогноз ECMWF IFS
   Open-Meteo и сохраняет его в data/weather_cache/.
3. src.tools.feature_tool добавляет физические и календарные признаки.
4. src.train.train_model обучает LightGBM до 31 декабря 2025 и проверяет её
   на январе 2026.
5. src.tools.inference_tool применяет модель локально, ограничивает прогноз
   диапазоном 0–1 и возвращает 0 при скорости ветра на высоте 100 м выше
   25 м/с.
6. src.agents.tools связывает погоду и модель, а
   src.agents.orchestrator последовательно вызывает оба инструмента.

## Запуск

1. Установите зависимости: python -m pip install -r requirements.txt
2. Обучите модель: python -m src.train.train_model
3. Запустите интерфейс: python -m src.app

Первый запуск обучения обращается к Open-Meteo и создаёт локальный
data/weather_cache/ и models/wind_power_lgb.pkl. Повторное обучение без сети:
python -m src.train.train_model --offline.

Чтобы активировать LLM-чат, создайте .env в корне проекта с двумя строками:

    OPENAI_API_KEY=your_key
    MOCK_MODE=false

Без ключа приложение запускается в demo-режиме, а локальные ML-инструменты
по-прежнему можно вызывать напрямую из Python.

## Проверки

1. python -m ruff check src
2. python -m compileall -q src

## Ограничение текущей версии

Погода в обучении и tools берётся из Historical Forecast API, поэтому
сквозной прогноз воспроизводим для исторических дат. Для продуктового
прогноза на будущие 24–48 часов следующим этапом нужно добавить отдельный
провайдер оперативного прогноза погоды, сохранив тот же контракт признаков.
